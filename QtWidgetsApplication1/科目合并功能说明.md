# 会计科目合并功能说明

## 1. 功能用途

部分账套在导入前，会因为多个原始科目共用了同一个科目编码而被系统拆分成多个不同编码的科目，并在 `PreImportReminders` 中提示相关问题。

“会计科目合并”用于在拆分完成之后，由操作人员自行判断哪些科目应当重新合并，并同步整理科目层级、期初余额和凭证中的科目引用。

功能入口：工作台 → 数据与维护工具 → **会计科目合并**。

支持输入 `AccountSet.json` 或包含 `AccountSet.json` 的 ZIP 账套数据包。处理过程中不会覆盖原始文件，最终生成新的 ZIP 数据包和科目映射 CSV 清单。

## 2. 处理范围

本功能只修改以下三项数据：

- `GLAccountList`：会计科目及其层级信息。
- `GLBalanceList`：科目期初余额。
- `GLVoucherList`：凭证中的科目编码。

`GLBalanceFullList` 不参与任何处理。`PreImportReminders` 及其他业务数据也保持不变。

## 3. 科目层级识别

系统不直接依赖原始数据中可能不准确的 `AcctParent`、`AcctLevel` 或 `AcctIsDetail`，而是根据科目编码的前缀关系重新识别科目树。

例如：

```text
1131                应收账款
├─ 1131.001         客户甲
│  └─ 1131.001.001  项目一
└─ 1131.002         客户乙
```

处理后，会按照真实科目树重新生成：

- `AcctParent`：直接父科目编码。
- `AcctLevel`：实际科目层级。
- `AcctIsDetail`：是否为末级科目。

如果发现相同的科目编码仍然对应多条科目记录，系统会要求先完成科目编码冲突拆分，再进行合并。

## 4. 可合并范围

只有父级相同的科目可以合并。

```text
允许：

1131.001 + 1131.002
父级均为 1131

不允许：

1131.001 + 1133.001
父级分别为 1131、1133
```

一级科目统一视为属于虚拟根节点，因此不同的一级科目之间也允许合并。

一次可以勾选两个或两个以上的同父级科目。末级科目和非末级科目都可以勾选；同一账套可以连续执行多次合并，最后统一生成输出文件。

## 5. 目标科目选择

每次合并时，可以从以下方式中选择目标科目：

1. 保留任意一个已勾选科目作为目标科目。
2. 新建一个与已勾选科目父级相同的目标科目。

新建目标科目时，需要填写：

- 新科目编码：系统会提供一个建议编码，也可以自行修改。
- 新科目名称：由操作人员指定。
- 余额方向：借方或贷方。

新编码不能与现有科目重复，也不能改变其他现有科目的父子关系。

## 6. 合并规则

### 6.1 末级科目与末级科目

两个或多个末级科目合并后，只保留目标科目：

```text
合并前：

1131.001 客户甲，期初 100
1131.002 客户乙，期初 200

合并后：

1131.001 客户甲，期初 300
```

原科目对应的凭证改为引用目标科目；会计年度、期间、币种和辅助核算维度相同的期初记录合并计算。

### 6.2 非末级科目与非末级科目

先合并选中的父科目，再比较其直接子科目的名称：

- 名称相同的子科目继续合并。
- 名称不同的子科目全部保留，并移动到目标科目下面。
- 子科目还有下级时，按照同一规则继续递归。

例如：

```text
合并前：

科目 A
├─ 北京
│  ├─ 项目一
│  └─ 项目二
└─ 上海

科目 B
├─ 北京
│  ├─ 项目一
│  └─ 项目三
└─ 广州

合并后：

目标科目
├─ 北京
│  ├─ 项目一
│  ├─ 项目二
│  └─ 项目三
├─ 上海
└─ 广州
```

其中，两边的“北京”和“项目一”分别合并；“项目二”“项目三”“上海”“广州”继续保留。

### 6.3 末级科目与非末级科目

如果末级科目与非末级科目合并，最终目标必须保留非末级结构。

系统会在目标科目下面增加一个名称与原末级科目相同的子科目，由这个新子科目承接原末级科目的期初和凭证：

```text
合并前：

往来 A                 末级科目，有期初及凭证

往来 B                 非末级科目
├─ 客户甲
└─ 客户乙

合并后：

目标科目
├─ 客户甲
├─ 客户乙
└─ 往来 A              承接原“往来 A”的期初及凭证
```

如果用户选择原末级科目作为目标，系统会先把该科目转换成非末级科目，再在它下面创建同名子科目承接原来的明细数据。

新增子科目的期初也会同步汇总到对应的非末级目标科目，保证父级期初能够反映本次新增的明细金额。

### 6.4 子科目重新编码

非同名子科目迁移到新父级时，会按照目标父级重新生成科目编码，并同步处理其所有下级科目。

系统优先保留原有子级编码片段；如果目标父级下已经使用该片段，则自动生成同级的下一个可用编码。

## 7. 期初余额处理

合并期初时，会以目标科目的余额方向为准：

```text
目标科目：借方

原科目 A：借方，期初 100
原科目 B：贷方，期初 40

合并结果：100 + (-40) = 60
```

具体规则：

- 原科目和目标科目方向相同：期初值直接相加。
- 原科目和目标科目方向相反：原科目的期初值取反后再相加。
- 期初金额、期初数量和期初外币金额按照相同方向规则处理。
- 累计借方、累计贷方等独立发生额分别相加，不互换借贷栏位。
- 不同年度、期间、币种或辅助核算维度的记录不会强行合并。

## 8. 凭证处理

凭证只修改 `AcctCode`，使原科目的凭证指向合并后的目标科目或自动新增的承接子科目。

以下内容保持不变：

- `DebitBal`：借方金额。
- `CreditBal`：贷方金额。
- 借贷数量、摘要、日期和其他凭证信息。

即使目标科目的余额方向与原科目相反，凭证的借方和贷方也不会颠倒。

## 9. 操作步骤

1. 打开工作台中的“会计科目合并”。
2. 从共享输入目录选择账套文件，或直接拖入 ZIP / JSON。
3. 在弹出的科目树中按编码或名称搜索。
4. 勾选至少两个父级相同的科目。
5. 选择保留其中一个科目，或者填写新目标科目的编码、名称和方向。
6. 点击“合并勾选科目”，查看更新后的科目树和合并记录。
7. 如需处理其他科目，重复勾选和合并；不支持撤销，操作失误时请取消并重新打开原始数据包。
8. 点击“生成合并后的 ZIP”，在共享输出目录查看处理结果。

科目树会同时显示“本科目期初”和“子树期初”。非末级科目合并时，其下级科目可能需要迁移并重新编码，因此实际调整的期初条数应以“子树期初”为参考，而不能只看当前科目自身的期初条数。

点击“合并勾选科目”后，系统会在真正应用合并前显示影响确认，包括新增/删除科目数、期初科目编码调整数、凭证科目编码调整数和期初金额取反数。其中“科目编码调整”只表示 `AcctCode` 发生变化；只有借贷方向相反时，期初金额才会取反。

每次合并重新组装科目、期初、凭证和根 JSON，避免连续合并时积累已替换的数据。写入及科目层级校验通过后才更新当前账套；JSON 存储超限或内存不足时提示失败，不提交本次结果。界面仅记录合并次数和文字日志，不保留撤销快照。

## 10. 输出文件

处理完成后，输出目录会生成：

```text
账套名称_科目合并.zip
账套名称_科目合并_科目映射.csv
```

ZIP 中包含更新后的 `AccountSet.json`。

CSV 包含以下列：

```text
SourceCode,SourceName,TargetCode,TargetName
```

可以通过该清单核对原科目编码、原科目名称、合并后编码和目标科目名称。
