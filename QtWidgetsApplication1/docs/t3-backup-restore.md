# 恢复 T3 备份包到数据库

入口：工作台 → 文件处理 → **恢复备份包** → 备份来源软件选择 **用友 T3**。

## 本机恢复

1. 从可配置并持久化的备份包目录选择备份，或拖入 `UFDATA.BA_`、标准 `.bak`、`UF2KAct.Lst`、包含备份的文件夹。
2. 确认所有实例共用的备份暂存目录，可编辑并持久保存，默认 `D:\Backup`。当前 Windows 用户需可写入，SQL Server 服务需可读取；跨本机/211 使用双方可访问的 UNC 共享目录。
3. 点击“读取备份与年度”，查看来源及兼容版本，程序自动匹配实例。
4. 在读取按钮下方确认或改选恢复实例。切换只校验目标连接、版本和暂存文件访问，不重新读取备份包；保留清单、勾选及目标库名。不兼容或访问失败时禁用恢复，可切回原实例继续。
5. 勾选年度，核对或修改目标数据库名，以及当前实例的数据、日志目录；确认后点击“恢复所选数据库”。本地实例使用当前 Windows 身份，需要具有恢复权限。

不需要安装 T3。支持 GZIP 封装的 T3 备份和标准 SQL Server 备份；暂不支持其它私有封装、拼接或分卷压缩包。

### 版本识别与直接恢复

读取备份时显示来源 SQL Server 版本和建议目标版本；优先保留当前兼容实例，否则自动选择兼容本地实例，最后考虑 211。选择结果显示在“恢复到”中，仍需用户核对并点击恢复。

SQL Server 2000 备份可直接恢复到 SQL Server 2005、2008、2008 R2；不能直接恢复到 SQL Server 2012 及以上。自动升级中转已移除，没有兼容实例时停止并提示。

扫描本地实例时保存引擎版本并显示到列表中。211 固定为已查询确认的 SQL Server 2008 R2 Express（10.50.4000.0、内部版本 661）。匹配先按版本记录筛选，再验证候选实例；未知备份不猜测版本。

## 远程恢复

1. 在“恢复到”下拉框选择“211 数据库”，服务器固定为 `192.168.1.211`，使用本机 SqlServer211.local.json 或环境变量中的 SQL 凭据，配置方法见 readme.md。
2. 备份暂存目录自动带出 `\\192.168.1.211\hzw`。默认勾选远端解压，请先在 211 服务器运行 `C:\hzw\LemonTransferAgent\StartAgent.cmd`，助手本地目录保持 `C:\hzw`。若未运行助手，可取消远端解压，改用本机解包后传输。
3. 工具在固定共享不可访问时使用本机配置的 Windows 共享凭据登录；未配置时先在 Windows 中连接共享，不保存持久映射，不断开已有共享会话。已有不同账号的连接导致冲突时会明确提示；自定义共享不使用此配置凭据。
4. SQL Server 服务账号也需有读取该目录的权限。工具通过 SQL Server 实际读取备份验证这一点。
5. 数据、日志目录是**服务器本机目录**，例如 `D:\SQLData`，不要求写成 UNC。
6. 读取年度、核对名称并恢复。

UNC 路径可在共享主机上右键文件夹 → 属性 → 共享 → 网络路径中查看。没有共享时需先由有权限的人配置共享和访问权限。共享名可以与磁盘文件夹名不同，不能从 `D:\Backup` 直接推断共享路径。

微软说明：网络备份设备使用 UNC 路径，访问由 SQL Server 服务账号执行。[Backup devices](https://learn.microsoft.com/en-us/sql/relational-databases/backup-restore/backup-devices-sql-server?view=sql-server-ver16)

## 输入目录与保护行为

- 备份包目录单独保存，用于文件选择；拖入留存仍使用 `RepairPathSettings` 的共享输入目录。
- 外部文件拖入后立即复制到输入目录；同名自动加后缀，已有文件不被覆盖。拖入目录或清单时定位实际备份文件后留存。
- 文件选择框选择、手工粘贴路径沿用原路径，不额外留存。
- 读取备份只准备暂存文件和年度清单。恢复必须点击恢复按钮。
- 拒绝目标系统库、重复目标名和已存在的数据库；不使用 `WITH REPLACE`。
- 批量恢复前检查全部目标库，并校验所选备份。数据和日志文件通过 `MOVE` 写到目标服务器目录，使用唯一文件名。
- 恢复期间可以停止后续年度；正在执行的当前数据库恢复会完成。失败会保留已成功恢复的库，并提示检查失败目标状态。
- 切换备份、连接配置或关闭页面时清理该页面创建的暂存文件；原备份和共享输入目录留存副本保留。
- 按用户授权将 211 SQL 和 Windows 共享凭据固定在代码中，不写入运行设置或日志。程序为 32 位，需要安装 32 位 ODBC Driver 17 或 18 for SQL Server。

## 自动创建采集控制库

- 无需填写账套名称、行业性质或会计准则。工具从整包首个年度的 `dbo.UA_Account_Ex` 按**备份原账套号**读取 `cAcc_Name`、`cTradeKind`，兼容有数据的 `dbo.UA_Account`，保持实际行业性质原文。首年度会恢复到唯一命名的临时信息库用于读取，完成或失败后定向清理；即使只勾选后续年度，也能使用整包的首年度信息。元数据提取和控制表登记预检均在目标年度恢复之前完成。
- 自动创建或复用 `UFSystem`，新增库的数据、日志文件使用页面指定的服务器目录与唯一文件名；控制表只包含采集所需四列 `cAcc_Id`、`cAcc_Name`、`iYear`、`cTradeKind`，不用于启动 T3 系统管理。
- 目标名必须是 `UFDATA_三位账套号_四位年度`，且年度与备份一致。需要避开同名库时，仅修改账套号；登记使用新账套号，年度库内的原始信息保持不变。
- 多年度登记为同一条账套记录，起始年度取已登记的最早年度，兼容采集器的账套列表与年度库扫描逻辑。
- 不覆盖已有不同名称或行业性质的账套登记，不改动现有控制表结构。信息缺失、结构不兼容或登记失败会明确报错；已恢复的年度库保留，日志区分“年度库已恢复”和“采集登记成功”。
- SQL Server 2000（数据库版本 539）备份仅在兼容实例上直接恢复；不再升级中转。选择 211 时，最终数据库在 211 上恢复并登记。

## 开发与验证

- 后端：`QtWidgetsApplication1/Common/T3BackupRestorer.h/.cpp`，负责格式识别、GZIP 流式解包、ODBC 连接、备份集读取、校验和恢复。
- 界面：`QtWidgetsApplication1/T3RestoreWidget.h/.cpp`，后台线程执行操作，复用输入目录和拖拽留存逻辑。
- 导航功能 ID 20；VS 项目启用 Qt SQL 模块。部署时需要 `Qt5Sql.dll` 和 `sqldrivers/qsqlodbc.dll`。
- 自动测试：`Tests/T3RestoreTests.pro`；在独立构建目录使用 Qt 5.12 MSVC Win32 的 qmake 和 nmake 构建。
- 默认测试覆盖格式、损坏/截断/CRC 错误、大小限制、取消、临时文件清理、SQL 转义、目标保护和拖拽交互。
- 集成测试通过临时环境变量配置：`T3_TEST_SOURCE`、`T3_TEST_SERVER`、`T3_TEST_USER`、`T3_TEST_PASSWORD`、`T3_TEST_STAGING`、可选 `T3_TEST_DRIVER`。未设置账号时使用 Windows 身份验证。
- `configuredConnection` 仅检查连接；`realWidgetAnalyze` 验证界面读取和失效状态；`realBackupRestore` 使用六年度样本创建 `UFDATA_987_<年度>` 与 `UFSystem`，仅在这些名称不存在时运行，验证后清理本次测试库。请只在授权的测试服务器执行。
- `controlRegistration` 在随机命名控制库中验证真实 SQL 登记、重复执行、准则/名称冲突和结构兼容性；`automaticMetadataRestore` 在本机生成临时备份，以 `989` → `988` 改名恢复验证自动读取、中文与单引号、原准则文本保留及最小控制库。仅在保留测试名和 `UFSystem` 均不存在时运行，完成后清理。
- `legacyRoutingAndTransfer` 验证版本拒绝、文件复制、取消及租约清理；`legacyDirectCompatibility` 通过 `T3_LEGACY_SOURCE` 只读检查旧备份兼容性。自动选择实例、缓存和路径设置由 `RestoreCompatibilityTests.cpp` 覆盖，不再执行旧中转测试。
