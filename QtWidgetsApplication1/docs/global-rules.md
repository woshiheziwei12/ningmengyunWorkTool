# 全局规则（活文档）

本文件记录当前生效的跨功能约定。调整全局行为时直接更新对应条目，保持规则与实现一致。

## Chrome 扩展中的云端账套功能

- `LemonChromeExtension/` 与 Qt 工程目录同级，提供网页内面板和独立工具页，复用当前 Chrome 登录进行备份下载、删除和专业版导账包上传；不依赖 Qt 运行时。安装加载 `LemonChromeExtension/unpacked/`，操作与验证说明见该目录源码的 `README.md`。
- 扩展按宿主页面识别正式/测试环境，调用与桌面端一致的 JWT、套餐、账套、备份、回收站和专业版导账接口；仅所选账套参与操作。读取/切换账号使旧选择失效，删除前复核目标身份并显示确认清单。
- 业务凭据仅驻留浏览器会话；业务接口请求通过单次临时规则携带套餐 Cookie，不修改网页 Cookie。统一扩展额外支持用户主动的桌面登录同步和当前网页 Cookie 获取/复制；不读取浏览器本地文件，不把凭据发往第三方。备份交给 Chrome 下载，确认下载完成后报告下载成功。
- 扩展上传通过文件选择/拖放读取浏览器 File，在内存副本上精确替换三个导账元数据数字字段，保留其他 JSON 原文与源文件。浏览器无桌面共享输入目录权限，因此本节不套用下文 Qt 拖入文件留存规则。ZIP 上限 128 MB、解压上限 256 MB，大文件继续使用桌面工具。
- 扩展使用 Node 离线接口与 DOM 测试，不启动 MSBuild。Chrome 实际安装、DNR 匹配及线上操作需单独验证；离线测试不等同真实账号联调，验证不得默认删除或上传用户账套。
- 浏览器原生 `fetch` 注入请求封装时必须保留全局作用域接收者，不可直接当作封装对象的方法调用。接口错误需标出阶段与接口域名/路径，隐藏查询参数及凭据；只读查询与可能已生效的写操作分别提示。离线测试额外模拟浏览器的原生调用接收者检查。
- `jproh5test2`、`jproh5test`、`jproh5graytest` 三个前端域名均路由到测试环境。浏览器扩展的测试套餐接口固定使用 `https://etest.ningmengyun.com`，避免站点 HSTS 将旧 HTTP 地址升级后导致单次认证规则与实际 URL 不匹配；错误提示保留协议。此浏览器适配不修改 Qt 的环境配置。

- 网页面板“登录 Cookie”按用户点击读取当前源页面 URL 和 Cookie Store 中的 `ningmengcookie`，不需要先读取账套，不回退到其他域名。默认遮挡，允许显示和复制，复制前重新读取；失败、切换页签、离开页面或 60 秒到期清除面板值，不改浏览器 Cookie。仅扩展面板可请求明文，不传给宿主页面、不写日志；原业务会话响应仍不暴露凭据。

## Qt 与 MSVC 编译兼容

- 主项目使用 Qt 5.12 和 MSVC v143。Qt 的 `QList` 等头文件仍调用 `stdext::checked_array_iterator`，新版 MSVC 将其标记为 STL4043 弃用项，现有 SDL 检查配置会产生 C4996 编译错误。
- 正式 `QtWidgetsApplication1.vcxproj` 在公共 `ClCompile` 配置中定义 `_SILENCE_STDEXT_ARR_ITERS_DEPRECATION_WARNING`，覆盖 Debug/Release Win32，并通过 `%(PreprocessorDefinitions)` 保留继承项。保留 SDL 检查，只对这一项第三方兼容提示进行抑制。
- 验证编译时，隔离配置只负责产物、中间文件和生成文件路径，不能额外注入正式项目缺少的兼容宏来掩盖正常构建问题。修改编译兼容配置后，使用正式项目分别验证 Debug、Release，遵守构建进程复核及原 EXE/PDB 哈希保护规则。

## 托盘、会话续期与环境切换

- 登录后关闭主窗口只隐藏到系统托盘，后台任务和授权续期继续运行；点击托盘恢复窗口。主界面环境菜单与托盘菜单均提供“退出工具”。无托盘服务时关闭退化为最小化，仍可用主界面菜单退出。
- 正式环境使用蓝色圆形 P 图标和蓝色页面背景，测试环境使用橙色方形 T 图标和暖色页面背景。窗口标题、托盘提示和每个页面的固定顶栏均显示当前环境；文字和形状同时区分，不能仅靠颜色。
- 登录授权不设置固定时长上限：Cookie 使用登录接口 `expires_in` 换算到期时间，JWT 使用 `exp`，取两者中较早的有效到期时间。只有一项有效时使用该项，两项均缺失时不猜测有效期，明确提示手动刷新。提前 1 小时续期，短于 2 小时的授权在有效期过半时续期。每 30 秒检查绝对时间，休眠恢复后补刷；计划内部按 UTC 计算，界面只转换一次为系统本地时间（北京时间为 UTC+8）。失败 5 分钟重试，并提供手动刷新和托盘提示。
- 续期复用当前进程内的密码登录流程，获取 Cookie、JWT 与套餐信息，全部成功且账号身份一致后一次发布授权；失败保留旧会话和原到期时间，不重复提交业务操作。已选择的套餐/账套不被续期覆盖。续期不额外写入密码，跨进程保存仍由“记住密码”控制；导账轮询每次发请求读取最新 Token。
- 登录后的环境菜单和托盘菜单可切换正式/测试环境，分别读取 `LemonApp.Pro.dat`、`LemonApp.Dev2.dat` 中保存的密码。无密码或自动登录失败时留在目标环境登录框；取消保留原环境。目标登录完成前暂停旧会话续期并禁用旧窗口；成功后销毁旧页面与会话，创建目标环境工作台，不复用账套选择与页面缓存。
- 切换或退出前检查所有页面的 `sessionBusy*` 属性、在途共享网络请求及模态对话框。异步任务、轮询等待、会泵送事件的同步任务都必须覆盖完整忙碌周期，避免切换到另一环境后旧请求继续执行。新增后台入口必须纳入此规则。
- 验证：`SubjectBalanceImportTests` 使用本机模拟接口验证 12/24/48 小时服务端有效期、缺失有效期、JWT 较短期限、刷新失败保留会话、并发刷新抑制、保存密码切换、轮询使用新 Token；不调用真实账号。`WorkspaceUiSmoke` 分别在 Pro/Dev2 验证托盘隐藏/恢复、环境菜单、忙碌标识以及两套页面截图。构建隔离与 PDB 清理仍遵守根规则。

## 工作区页面与功能分类

- “打开柠檬云官网”使用系统默认浏览器配合统一的 `LemonChromeExtension/unpacked/`（“柠檬云账套工具”）同步当前桌面账号后打开对应官网；正式为 `wbgate`，测试为 `etest`，浏览器跳转统一 HTTPS。备份/删除/上传、登录同步及网页 Cookie 获取共用一个扩展，浏览器需设为默认 Chrome；缺少扩展时本机说明页提供安装步骤及不切换账号直接打开官网的入口。
- 每次点击仅在 `127.0.0.1` 临时端口创建 60 秒有效的连接，使用随机 256 位一次性票据、固定扩展 ID、Host/Origin 检查和有界请求；Cookie 仅通过扩展后台领取，不出现在网址、页面、日志或临时文件中。领取后立即清除桌面端副本，超时/完成/取消关闭监听；全过程设置 `sessionBusyBrowserLogin`。不启动独立浏览器配置或常驻后台服务。
- 登录助手只操作当前标签页 Cookie Store 中适用于目标网关的 `ningmengcookie`，先在内存保留原值及属性，清除重叠同名项，再写入 `.ningmengyun.com` 会话 Cookie（Secure、SameSite=Lax）并核对有效值；失败尝试恢复原登录，其他 Cookie 保留。Chrome 删除重叠同名 Cookie 时可能同时影响域 Cookie，不能先写新值再删旧项。正式/测试环境共用此域名 Cookie，点击会切换浏览器中的柠檬云账号，不伪造服务端登录有效期。同步流程使用 Cookie API 和本机连接；扩展还保留账套功能所需权限，并新增 clipboardWrite 供用户主动复制，不持久化 Cookie 副本。
- 验证入口：`Tests/BrowserLoginBridgeTests.cpp` 的真实本机 HTTP 测试、`LemonChromeExtension/tests/login-sync.test.js` 的扩展逻辑测试，以及 `browser-e2e.mjs` 的独立 Chrome for Testing 测试。所有测试使用合成凭据，浏览器测试拦截官网导航，不视为真实账号登录成功验证。安装及操作说明见 `LemonChromeExtension/README.md`。
- 桌面程序所有 `QComboBox` 禁止用滚轮直接切换当前选项，无论是否获得焦点；覆盖登录页、功能页及动态创建的弹窗。`main.cpp` 在创建窗口前安装全局事件过滤器。展开列表后仍可滚轮浏览选项，点击选择、键盘操作及可编辑下拉框的输入保持可用。验证时分别检查普通/可编辑下拉框在有无焦点时的上下滚轮、展开列表滚动、点击与键盘选择，以及页面滚动。
- 登录页继续使用原有样式。登录后的主窗口单独加载 `QtWidgetsApplication1/Resource/qss/workspace.css`，主题通过窗口父子关系覆盖功能页及其对话框，禁止通过 `QApplication::setStyleSheet` 改变登录页。
- 工作台提供五个分类入口、常用快捷入口和全局功能搜索；分类页各自保留搜索条件与滚动位置。恢复备份入口合并为 ID 20，旧恢复 ID 作为兼容路由保留；其他功能 ID 保持不变。分类对应关系统一由 `FunctionSelectWidget::categoryForFunction` 定义。
- 云端账套：删除账套、备份下载、上传专业版账套、科目余额表导账。科目整理：编码冲突、同级重名、编码分隔符、空名称修复、名称空白清理、科目合并。凭证修复：辅助核算非必录、日期异常、引用科目编码、非末级科目转换、凭证编号修复。文件处理：整套修复、Access 2003 转换、恢复备份包、选择删除数据库、指定年度数据截取。查询与会话：JSON 查询、复制登录 Cookie、企业微信文档读取。
- 共 23 个入口，其中指定年度数据截取仍为“规划中”，保留原说明提示；不计入 22 项可用工具。
- 工具页的返回按钮回到所属分类。左侧导航可随时切换分类或工作台；切换仅改变显示，不取消正在执行的业务任务。
- 功能页面使用可滚动容器，小窗口通过滚动访问完整表单；主窗口宽度小于 1040 时折叠为带提示文字的紧凑导航，卡片按可用宽度调整为一至三列。
- 科目余额表导账的来源软件下拉框支持输入名称片段搜索，不区分英文大小写（如“金蝶”“用友”“t3”）。输入内容仅用于筛选，必须从候选或下拉列表选择实际软件才能提交，编辑查询后立即清除旧软件选择及其文件配置，不新增任意软件类型。清空关键词后下拉恢复完整目录。
- 该导账页面的下拉框与软件搜索候选统一采用样式化选项代理，行高至少 36px 且随字体高度增加，上下留白并保留行间距，避免默认菜单代理造成文字覆盖；软件名称较长时可悬停查看完整名称。`SubjectBalanceImportTests::softwareSearchAndPopupSpacing` 覆盖关键词匹配、中文输入、候选选择、无匹配防误提交及实际选项矩形间距，并生成弹层截图。
- 主窗口统一表格间隔行底色、行高和状态文字对比度。按钮颜色区分常规操作、辅助操作及删除操作，禁用态必须清晰可辨。

### 页面验证

`Tests/WorkspaceUiSmoke.cpp` 是离线界面验证入口，仅在隔离构建中替代 `main.cpp`；正式程序仍执行原登录流程。验证五个分类共 23 个入口、全局搜索及空结果、19 条可离线打开的工具路由及 5 条旧恢复兼容路由、返回所属分类、800×480 小窗口、云端列表和科目冲突弹窗，并保存实际 Qt 页面截图。云端列表仅直接构造页面，不调用网络加载；不触发删除、上传、文件处理、扫码登录或复制 Cookie。

可通过 MSBuild 的 `ForceImportBeforeCppTargets` 属性显式导入 `Tests/WorkspaceUiSmoke.targets`，并将 `TargetName` 设为 `WorkspaceUiSmoke`；运行时传入截图目录。测试使用 Windows 平台插件及 `WA_DontShowOnScreen` 离屏绘制，保留系统字体，同时不弹出测试窗口。运行环境的 `APPDATA`、`LOCALAPPDATA` 也需指向隔离目录。

构建时遵循根规则隔离 `OutDir`、`IntDir`、Qt 生成路径与 `TLogLocation`，记录并复核原启动 EXE/PDB 的存在状态和 SHA-256。

## 企业微信文档读取

- ID 28 位于“查询与会话”。仅支持固定的运营支持组文档，以本地当天日期读取当天及之后的日期工作表。无年份表名使用文档标题中的年份；非日期表跳过，不取历史表代替空结果。
- 用独立 WebView2 配置目录承载官方扫码页面及同源读取，不复用柠檬云请求管理器、TLS 配置或登录凭据。WebView2Loader.dll 随主程序部署；未发起该功能的登录或读取时，不启动浏览器进程。
- 企业微信登录成功及读取完成时，将该独立浏览器内适用于文档域名的 Cookie 用 Windows 当前用户 DPAPI 加密、原子保存到配置目录 `session.dat`。重启在导航前恢复缺失项，保留浏览器中已有项及服务器原到期时间，过滤过期项；不设置固定授权时长，不视本地文件存在为授权有效。获取时先联网验证，未完成验证时提供官方登录页。保存期间保持忙碌，保存失败单独提示。
- 读取、登录等待、异步轮询全过程设置 `sessionBusyWecomRead`，纳入退出及环境切换检查；停止后迟到回调不得修改结果。版本不一致、未支持协议、读取失败及部分结果均明确标记。
- `WecomDocumentReader` 提供数据接口，页面展示与 JSON 导出复用同一快照。导出保留原始坐标、文本、链接及数字原值，不导出 Cookie、分享码等会话信息。完整协议边界、运行依赖与验证方法见 [企业微信文档读取](wecom-document-reader.md)。
- 进入工作台即启动当前 Windows 用户专属的命名管道读取接口，托盘运行时继续可用；外部调用通过 `Tools/Read-WecomDocument.ps1` 获取 JSON。仅支持状态查询和固定文档当天及之后数据的实时读取，不接收 URL、凭据、文件路径或写操作。请求复用页面与登录会话，忙碌时拒绝重复读取；授权待确认时返回 `login_required` 并提供官方登录页，不以缓存冒充最新结果。
- 管道使用 `UserAccessOption`，不启动 HTTP/TCP 监听；每个用户只允许一个实例提供接口，锁冲突在文档页面提示。接口任务设置 `sessionBusyWecomBridge`，保持至底层读取完成；客户端断开不启动重复请求。状态查询不创建浏览器、不表示授权有效。测试端点与真实工具隔离，不占用生产管道。

## 拖入文件时留存到共享输入目录

所有支持向页面拖入本地文件的功能，在接受文件的 `dropEvent` 中先将文件复制到 `RepairPathSettings::inputDir()`，复制成功后使用留存路径继续原有流程。复制发生在拖入时，不等待点击处理按钮；仅悬停拖动不复制文件。

- 源文件保留原位，拖放结果为复制；拖放来源仅允许移动时拒绝接收。输入目录不存在时自动创建。
- 保留原文件名；遇到同名文件时依次使用 `原名_2.扩展名`、`原名_3.扩展名`，不覆盖已有内容。重复拖入外部文件也按此规则留存。
- 文件经规范路径解析后已位于共享输入目录或其子目录时，直接复用，避免自我复制。
- 复制失败时显示错误，不使用该文件继续处理；多文件入口仍可处理其他复制成功的文件。
- 每个功能原有的格式限制、一次接收数量、自动开始处理或等待点击的行为保持一致。Access 2003 原有目录拖放行为继续保留；本条复制规则适用于直接拖入的文件，不扩展为递归留存整个目录。
- 文件选择按钮、粘贴路径不因本条规则而自动增加复制行为；已有复制行为继续保留。

### 备份版本、实例版本与自动匹配

- 扫描本地实例时读取 64/32 位注册表中的引擎 `MSSQLServer/CurrentVersion/CurrentVersion`，缺失才回退 Setup PatchLevel/Version；版本与扫描时间按实例地址持久化，下拉框显示产品代次和完整版本号。引擎版本优先于安装包版本，例如本机 SQL2008R2 的 Setup 为 10.52.4000.0，而引擎为 10.50.4000.0。缺失版本明确标为未知，不编造。
- `Common/SqlServer211.h` 固定保存经 2026-09-30 只读查询确认的 211 信息：SQL Server 2008 R2 Express、10.50.4000.0、数据库内部版本 661。扫描不连接 211；匹配采用固定值，实际读取仍连接目标获取路径并验证运行版本。
- T3、U8、T+、金蝶、浪潮统一记录备份头 `SoftwareVersionMajor/Minor` 和 `DatabaseVersion`。它们与数据库兼容级别不同，不能据兼容级别推断可降级恢复。支持已知 SQL Server 2000–2025 备份来源，工具目标为 SQL Server 2005–2025；未知来源或目标信息不足时阻止自动选择和恢复。
- SQL Server 2000 备份提示可使用 SQL Server 2005、2008、2008 R2；2005 及之后备份不得恢复到更低的引擎版本，2008 与 2008 R2 分开比较，内部数据库版本也不得高于目标。多备份集取共同兼容范围；没有交集时提示拆分。
- 点击读取后先保留可用且兼容的当前实例，否则优先其余本地实例，最后考虑列表中的 211 作为最终恢复目标。已获取备份版本后先用扫描缓存/211 固定版本筛选，符合的本地候选再只读查询实际运行版本；旧实例连备份头都读不出时，可继续尝试其他候选。包内容/权限等非版本错误在兼容实例上直接报告，不继续换目标掩盖错误。
- 成功后更新实际目标下拉框、服务器数据/日志目录和备份清单，共享暂存设置不随实例切换变化；在页面提示来源版本、建议版本、所选地址及版本；仅完成分析，不自动恢复。没有兼容实例、版本不明或取消时不启用恢复。恢复开始前再次校验实际版本，已彻底移除 T3/KIS 自动中转引擎。
- 兼容判定依据：[Microsoft RESTORE HEADERONLY](https://learn.microsoft.com/en-us/sql/t-sql/statements/restore-statements-headeronly-transact-sql)、[RESTORE 兼容说明](https://learn.microsoft.com/en-us/sql/relational-databases/backup-restore/restore-database-general-page)、[SQL Server 2012 升级参考](https://download.microsoft.com/download/9/5/3/9533501a-6f3e-4d03-a6a3-359af6a79877/sql_server_2012_upgrade_technical_reference_guide_white_paper.pdf)。版本兼容不代替文件权限、备份完整性和实际恢复校验。

## T3 备份恢复

- 统一“恢复备份包”（ID 20）中的用友 T3 选项；备份包目录独立持久化，拖入文件留存仍使用共享输入目录。
- 拖入 UFDATA.BA_、标准 .bak、UF2KAct.Lst 或备份目录时，解析实际备份文件并复用 `RepairInputFileUtils` 立即留存；不会递归复制整个目录，也不会自动恢复数据库。
- 目标服务器通过公共下拉框选择检测到的本地 SQL Server 实例或“211 数据库”：本地实例固定使用 Windows 身份验证；211 固定连接 `192.168.1.211`，使用本机配置或环境变量提供的 SQL Server 凭据，并自动带出 `\\192.168.1.211\hzw`。页面不提供服务器、账号或密码输入框。凭据读取规则见 readme.md：本机 SqlServer211.local.json 被 Git 忽略，也可用环境变量覆盖；不得把密码写入源码或日志。
- T3“恢复到”下拉列表使用 `QStyledItemDelegate` 应用选项样式，选项最小内容高度 28px、上下留白各 6px、左右留白各 12px，弹层内边距 4px，避免默认菜单代理导致选项挤在一起。
- 访问固定的 211 `hzw` 共享时，目录不可访问则使用本机配置的 Windows 共享凭据建立非持久 SMB 连接；缺少配置时提示先配置或通过 Windows 连接；不向其他服务器或其他共享发送该凭据，不自动断开已有连接。账号冲突时明确报错并保留已有会话。
- 输入目录和 SQL Server 备份暂存目录用途不同。远程恢复需要双方可访问的 UNC 暂存目录；共享文件夹由当前 Windows 身份访问，数据库账号不等于共享目录账号。
- 先解包并读取年度清单，再由用户勾选完整备份集、核对目标名称和服务器数据/日志目录后点击恢复。拒绝恢复到系统库或覆盖已存在的数据库，不使用 REPLACE。
- 采集要求原库和目标库名为 `UFDATA_三位账套号_四位年度`，目标年度保持不变，重名时可修改三位账套号。
- 恢复时自动创建或复用 `UFSystem.dbo.UA_Account`，只提供采集必需的 `cAcc_Id`、`cAcc_Name`、`iYear`、`cTradeKind`；不构建完整 T3 系统。从备份包首个年度的 `dbo.UA_Account_Ex`（无数据时兼容 `dbo.UA_Account`）按原账套号提取名称和行业性质，年度恢复为 ONLINE 后将原值登记到目标账套号，不要求用户填写、不猜测准则、不修改年度库元数据。
- 同一账套登记为一条记录，`iYear` 为已登记年度中的最小值；名称或行业性质与已有登记冲突时拒绝更新，事务回滚。已有控制表不改结构，缺必需列或存在不能自动填写的额外必填列时明确失败。年度库已恢复但读取信息或登记失败时保留年度库并报告部分完成，不计作完整成功。
- 操作在后台线程执行。读取期间可取消；恢复期间“停止后续恢复”等待当前数据库恢复完成后停止。失败时保留已成功恢复的库，提示检查失败目标状态，不自动删除数据库。
- 解包暂存文件在页面释放或重新读取时清理；输入原件保留。SQL Server 的版本兼容限制不通过解包绕过。
- 已移除 T3 和金蝶共用的 211 自动升级中转代码及入口。任何版本不兼容均不能触发远端建临时库、重新备份或回传；读取只准备文件并查询备份头，恢复仍须由用户点击。

## 选择删除数据库

- 功能 ID 21，位于“文件处理”；实现为 `DatabaseCleanupWidget` 和 `Common/DatabaseCleaner`。
- 下拉框支持检测到的所有本地实例（Windows 身份验证）与 `192.168.1.211`（本机配置的 SQL Server 凭据）。此功能不提供服务器、账号、密码输入框，驱动自动选择已安装的 32 位 ODBC Driver 18 或 17。连接失败不会改用其他实例；错误输出过滤配置密码。
- 点击读取后枚举清单，要求当前连接具有 sysadmin 权限，以免漏掉无权查看的数据库。保护数据库 ID 1–4、32767、系统库名、distribution 及 `is_distributor=1` 的自定义分发库。
- 数据库名称前提供复选框，读取或刷新后默认全不选；全选按钮在全选后切换为取消全选，并实时显示已选数量。至少勾选一项才能删除，执行期间锁定勾选；确认框仅显示所选数据库的数量及清单，不要求输入密码或确认文字。切换实例立即清空旧清单和勾选。
- 后端仅接收和删除用户勾选的数据库；空选择直接拒绝。删除时使用读取清单时保存的本地实例地址重新连接，并在删除前重新比对连接地址、实际实例及所选数据库的 ID、名称、创建时间和快照来源，所选项变化时停止并要求刷新；新增或变化的未选库不扩大删除范围。已选快照先于已选源库删除，源库存在未选快照时报告失败并提示补选，不自动删除未选快照。每个 SQL 批次再次核对身份和系统库保护。
- 在线普通库在同一批次内执行 SINGLE_USER WITH ROLLBACK IMMEDIATE 和 DROP；快照及非在线库直接 DROP。删除失败时尝试恢复原访问模式，记录错误后继续处理其他库；最终重新读取剩余非系统数据库，不将未核实状态报为成功。
- 后台执行，可停止后续删除；已执行的删除不回滚。切换页面不取消任务；关闭页面时等待当前操作结束。离线数据库被 SQL Server 删除后可能保留物理文件，此功能不额外删除文件系统中的文件。
- `Tests/DatabaseCleanerTests.cpp` 使用内存会话验证系统库保护、同名重建、实例切换、新增数据库、快照顺序、部分失败、取消、最终复核及特殊名称转义；由 `Tests/WorkspaceUiSmoke.targets` 一并编译运行。界面验证检查本地实例选项及固定 211 选项、无凭据输入、逐项勾选、全选和取消全选、计数、确认范围、取消、执行中锁定及刷新重置，不连接或删除真实实例。
- SQL 行为依据：[Microsoft DROP DATABASE 文档](https://learn.microsoft.com/en-us/sql/t-sql/statements/drop-database-transact-sql?view=sql-server-ver17)、[系统数据库说明](https://learn.microsoft.com/en-us/sql/relational-databases/databases/system-databases?view=sql-server-ver17)。

## 公共远端文件传输

- 压缩、上传、SHA-256 校验、服务器解压和文件租约清理由 `Common/RemoteFileTransfer` 提供，业务页面不得自行实现另一套传输。
- `RemoteTransferAgent` 为独立常驻助手，监视共享对应的本地目录；通过 `.lemon-transfer` 交换固定格式任务，无额外监听端口，不接收或执行命令。
- 公共接口支持任意单文件本地 GZIP 压缩上传，或调用方明确声明的已有 GZIP；不包含 T3/SQL 格式判断。T3 功能仅调用接口并使用返回的服务器本地路径。
- 任务采用随机 ID 隔离，校验压缩包大小与 SHA-256，限制压缩输入 8 GiB、解压输出 64 GiB；拒绝任务目录重解析点和路径穿越。
- 返回文件带共享租约，调用方持有租约期间文件有效，最后一份释放后清理本任务文件。取消正在处理的任务通过标记交给助手清理，不递归删除未知内容。
- 助手默认本地目录为 `C:\hzw`，可通过界面或 `--root` 指定；T3 页面填写对应 UNC 目录。Windows 共享凭证沿用系统登录，不写入任务文件。

- MSVC 2017 编译的助手及公共模块中文提示使用 `QString::fromUtf8(u8"...")`，避免旧编译器对 `QStringLiteral` 宏实参错误转码；`Tests/AgentEncodingCheck.py` 校验实际窗口文本与后端提示。
- Windows 元数据读取允许 `FILE_SHARE_DELETE`，以配合原子替换；短暂写入失败会重试，心跳文件被占用不能令常驻助手退出。

- 可扫描公司目录下多个年度、月度备份。账号支持字母和数字（如 B188、B176）。每年度只选一个快照，页面默认按末笔凭证日期、凭证明细数、已审核行数排序推荐，用户可改选；同年重复选择直接拒绝，禁止叠加累计月度快照。
- 账套名称优先读取 `Message=`，缺失或空白时使用用户所选目录名。批量恢复所选年度的名称及原账套号必须一致。新建 `USER<目标账套号><年度>` 并在 PUBDATA.unit 登记一条账套记录，启用日期为所选最早年度 1 月 1 日，只用于采集兼容，不承诺原软件完整运行。
- 复用本地/211 实例选择及身份验证，SQL Server 2008 及以上均可；逻辑数据直接写数据库，无需上传到 SQL 共享暂存目录。预检所有目标库和登记号重名，已存在则拒绝覆盖。所选年度的数据及账套登记在同一事务提交；失败/取消先回滚，再仅清理本次创建且随机物理文件标识匹配的库，清理失败列出保留库。现有控制表不改结构、不删行。
- 文件夹拖入直接使用该目录；VAL 文件拖入需把 VAL 和同目录 TX_ 整组复制到共享输入目录的随机子目录，保留原目录名用于名称回退。不会孤立复制 VAL 后丢失其依赖表，也不递归复制附件目录。
- 保留凭证审核状态。新版采集器按 shbz=1 读取凭证，项目明细关联必须包含月份和科目，旧版缺少条件会导致金额串联。恢复功能不更改采集器业务逻辑。
- `Tests/XinZhongDaRestoreTests.pro` 覆盖名称回退、字母账套号、解码损坏/截断/取消、已知布局、两种编码、多年扫描及重复年度保护。真实样本测试由 `XZD_TEST_ROOT` 启用，只创建随机账套号和随机控制库，检查多年度采集查询、原文件回读及数据库完整性，结束仅清理测试库。
