# T+ 备份恢复

入口：工作台 → 文件处理 → **恢复备份包** → 备份来源软件选择 **畅捷通 T+**。

读取备份时显示来源版本和兼容范围，并自动选择兼容实例；优先保留兼容的当前目标，再选择其他本地实例，最后考虑 211，不进行中转。扫描时保存本地实例版本；211 固定版本为已确认的 SQL Server 2008 R2 Express 10.50.4000.0。备份包目录和所有实例共用的暂存目录可调整并持久化。

1. 选择备份并确认所有实例共用的暂存目录。
2. 选择或拖入 T+ ZIP 备份包，点击“读取 T+ 数据库清单”。本地暂存默认 `D:\Backup`，也可指定 SQL 服务可读取的目录。
3. 在读取按钮下方确认自动匹配的实例，可手动改选。切换保留备份清单、勾选及库名，只校验目标连接、版本和暂存文件访问，不重新读取备份包。核对目标业务库名及服务器数据/日志目录。重名时修改目标名称，保留 `UFTData` 前缀。
4. 点击“恢复所选数据库”。业务库 ONLINE 且控制库登记完成才报告完整成功。

## 控制库

所给样本仅含一个 SQL Server 业务库备份和 `AdditionalXml.xml`，没有独立的控制库备份文件。

功能根据导账工具源码 `SQLServer/Chanjet/tplusstdexporthandler.h` 的账套列表查询和 `.cpp` 的 `InitAccountSet()` 查询，重建或复用 `UFTSystem.dbo.EAP_Account`：

| 控制库字段 | 来源 |
| --- | --- |
| DsName | 本次恢复的目标业务库名称 |
| cAcc_Name | XML 的 AccountName |
| iYear | XML 的 Year |
| iDuration | XML 的 Duration |
| VersionNo | XML 的 VersionNum |

此控制库满足导账工具的数据采集查询，用于恢复账套列表及启用信息；并非完整 T+ 系统管理库，不能据此启动原 T+ 软件。

## 保护和限制

- 不使用 REPLACE，不覆盖已有库或已有同名登记。已有控制表缺列、有额外必填列或其他不兼容约束时，在业务库恢复前报错，不自动修改表结构。
- ZIP 须含一个业务备份和一个 AdditionalXml.xml。流式解包到独立临时目录，使用固定输出文件名；拒绝不安全路径、多备份、重复清单、超限内容和无效 XML。
- 清单 DsName 必须与备份原库名一致。恢复前重新读取备份身份并使用实际 MOVE 目标执行 VERIFYONLY。
- SQL Server 版本须兼容。来自 SQL Server 2012 的本样本不能恢复到 `.\SQL2008R2`。
- 失败后保留已恢复的业务库，并显示控制库登记是否完成；不会将部分完成报告为成功。恢复中的停止请求等待当前库恢复及登记完成。
- 拖入文件立即复制到共享输入目录，不覆盖同名文件；选择文件和粘贴路径不增加这份留存。源 ZIP 不修改。
- 远端使用现有 UNC 共享传输或传输助手。仅在用户选择远端时连接远端，不自动切换实例。

设置 `TPLUS_TEST_SOURCE` 为上述 ZIP，`TPLUS_TEST_STAGING` 为 SQL 服务可读的本地目录后，运行 `TPlusRestoreTests.exe` 可执行真实恢复。使用随机 `UFTData_Test_<GUID>` 业务库与 `TPlusTestControl_<GUID>` 控制库，不写正式 UFTSystem；验证导账工具使用的字段、重名/取消/过期清单/不兼容控制表保护和 DBCC CHECKDB，结束后按记录的库名及物理文件清理。
