# U8 备份包恢复

入口：工作台 → 文件处理 → **恢复备份包** → 备份来源软件选择 **用友 U8**。

读取备份时显示来源版本和兼容范围，并自动选择兼容实例；优先保留兼容的当前目标，再选择其他本地实例，最后考虑 211，不进行中转。扫描时保存本地实例版本；211 固定版本为已确认的 SQL Server 2008 R2 Express 10.50.4000.0。备份包目录和所有实例共用的暂存目录可调整并持久化。

1. 选择备份并确认所有实例共用的暂存目录。
   本地备份暂存默认使用 `D:\Backup`，手动清空后仍使用此目录；读取备份时自动创建不存在的目录。也可自行选择其他暂存目录。
2. 选择 `UFDATA.BA_` 或 `UFDATA.BAK`，也可拖入 `UfErpAct.Lst` 或备份所在目录。目录优先选择 `UFDATA.BA_`；外层 GZIP 自动解包并校验完整性。拖入会将实际备份留存到共享输入目录；文件选择和粘贴路径不复制原件到输入目录。
3. 点击“读取 U8 数据库清单”，默认勾选全部完整备份集。
4. 在读取按钮下方确认自动匹配的实例，可手动改选。切换保留备份清单、勾选及库名，只校验目标连接、版本和暂存文件访问，不重新读取备份包。核对目标库名和服务器数据、日志目录。需要避开重名时，统一修改各行三位账套号，例如 `UFDATA_404_2022` / `UFMeta_404` 同时改为 `UFDATA_405_2022` / `UFMeta_405`。
5. 点击“恢复所选数据库”，等待日志显示所有所选库 ONLINE 且 U8 采集登记成功。

## 本次样本

`D:\test\用友u8\备份包需要帮忙恢复`

- U8 V16.500，404 账套，北京驰为律师事务所。
- SQL Server 2016（13.0.4001.0）生成的原生压缩备份，文件头为 `MSSQLBAK`。
- 备份集 1：`UFDATA_404_2022`，业务库中含 2022—2026 年数据。
- 备份集 2：`UFMeta_404`，元数据库。
- 一个业务库包含多个年度，**不需要创建五个年度数据库**。
- 此样本请使用已验证的本机 SQL Server 2022。211 的旧版本实例不能将高版本备份降级恢复。

## 旧版 GZIP 多年度样本

`D:\test\用友u8\需要恢复\1` 为 U8 V8.510 的 001 账套；`UFDATA.BA_` 外层是 GZIP，解包后是 `TAPE` 格式，包含 `UFDATA_001_2007`—`UFDATA_001_2026` 共 20 个年度库，内部数据库版本为 539。

2026-09-21 已在本机 `.\SQL2008R2` 完成整包恢复验证：20 个年度库均 ONLINE，账套启用年月及 20 条年度映射登记通过；使用空闲的测试账套号和随机控制库，测试后清理。此类旧版备份应选择已验证的 SQL2008R2 实例，当前 U8 功能不做旧版升级中转。

暂存目录需要当前 Windows 用户可写、SQL Server 服务账户可读。SQL2008R2 的安装目录及用户个人 Temp 目录可能不满足这两个条件；可在页面指定双方能访问的本地目录。

真实回归入口：设置 `U8_LEGACY_TEST_SOURCE` 为本样本目录、`U8_TEST_SERVER=.\SQL2008R2`；测试进程 `TEMP`/`TMP` 设为 SQL 服务可读的测试目录，运行 `U8RestoreTests.exe legacyBackupRestore`。仅检查解包及清单时可设置 `U8_TEST_ANALYZE_ONLY=1`。

## 登记与保护

先校验全部目标名称、备份身份和备份内容，再通过唯一命名的临时信息库读取原始账套信息。临时库清理时核对数据库文件归属。随后预检采集登记，依次恢复各库，全部 ONLINE 后用一个事务登记 U8 账套与业务库映射。

自动读取 `UA_Account_Ex`（无记录时兼容 `UA_Account`）的账套名称、单位名称、会计准则、启用年度和月份。恢复后创建或复用 `UFSystem`：

- `UA_Account`：`cAcc_Id`、`cAcc_Name`、`cUnitName`、`iYear`、`iMonth`、`cTradeKind`。
- `UA_AccountDatabase`：`cAcc_Id`、`cDatabase`、`iBeginYear`；只登记 UFDATA 业务库。

目标重名、已存在同号账套登记或已有控制表结构不兼容时拒绝操作，不覆盖原库、原登记、不自动变更已有表结构。已有 T3 四列控制表不满足 U8 字段要求时会在目标库恢复前报错。更改目标账套号不改写业务库内的原始账套身份。

控制库是为现有 U8 采集器准备的最小结构，不用于启动 U8 软件的系统管理功能。至少勾选账套首个业务库；建议保留默认的全部勾选。

取消会等待当前 SQL 操作完成再停止后续恢复。失败或取消后保留已恢复目标库；整组未完成登记时不会报告完整成功，日志列出已保留库。重试前应检查这些库并使用新的目标账套号，或通过已有数据库管理功能处理。

远程恢复复用公共文件传输模块，可使用已连通的 UNC 共享或公共传输助手；默认直接复制已压缩的备份并核对 SHA-256。目标 SQL Server 版本须兼容，不走 T3 的旧备份升级中转。

## 验证

- `Tests/U8RestoreTests.pro`：格式/清单、命名保护、拖放留存、实例切换清空状态。
- 设置 `U8_TEST_SOURCE` 为本样本路径，启用真实恢复测试；本机 Windows 身份验证，使用未占用的 970—989 测试账套号与随机 `U8TestControl_<GUID>` 控制库，不写入正常 `UFSystem`。测试完成定向清理。
- 本样本实际恢复验证：业务库和元数据库均 ONLINE，2022—2026 年度范围、账套启用年月及原准则文本、改号后的业务库映射、原库内 404 身份保留、同名拒绝、取消后不登记部分账套、两个库的 `DBCC CHECKDB` 均通过。
- 离线工作台验证：22 个入口、5 个分类、18 条本地路由、小窗口及返回所属分类通过。
- 构建使用独立产物/中间目录，原启动 EXE/PDB 的存在状态与 SHA-256 保持一致。测试恢复未留下正式 404 账套库。
