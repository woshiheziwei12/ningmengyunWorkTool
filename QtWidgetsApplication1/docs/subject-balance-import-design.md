## 服务端核查结果

- 客户端入口为 `POST api/ImportFromOther/ImportAsFromClientBatch`，要求登录认证；业务参数位于 query，附件使用 multipart/form-data，响应 `Data` 为异步任务编号。
- 入口新建账套；企业专业版需要当前套餐的 `serviceId`。请求还包含 `software`、`asName`、`asStartPeriod`、`accountingStandard`、`taxType`、`isZeroImport`、`accountSetVersion` 和 `importSystem`。
- 按已确认的企业专业版范围，请求使用 `accountSetVersion=2`、`importSystem=1`，不能沿用接口的标准版默认值。
- 服务代码列出 70 个来源软件/模板。核心附件字段为 `trialbalance`（余额表）、`voucher`（凭证表）、`subject`（科目表）；部分软件还有专用附件。
- `GetOptionalSubjectFileSoftwareList` / `GetRequiredSubjectFileSoftwareList` 描述的是科目表状态，不是完整附件配置。完整附件要求仍需逐个核对解析器，不能据此推断全部软件的必填字段。
- 客户端入口最终启用月份取所填月份和最早凭证月份的较早者；不能把输入年月直接当作保证采用的最终年月。
- 服务端会计准则枚举包含 1、2、3、4、5、6、7、9；具体软件的准则限制需结合解析器校验。纳税人类型为 1（小规模）、2（一般）。
- `isZeroImport=2` 为默认不导入零或空余额行，1 为导入。

## 整体方案

### 页面

- 在“云端账套”分类增加“科目余额表导账”，可通过工作区搜索进入，返回该分类；采用现有工作区样式和小窗口滚动布局。
- 表单包含来源软件、新账套名称、启用年月、会计准则、纳税人类型、导账域名，以及默认关闭的“导入零余额科目”。会计准则默认小企业、纳税人类型默认一般纳税人，用户可修改。
- 软件覆盖服务端现有 70 个枚举项；核对并保存对应附件槽位、必填状态和文件类型。服务端新增且本地尚无附件配置的软件应明确提示不受支持，不能套用错误的通用表单。
- 根据所选软件显示余额表、科目表、凭证表及专用附件入口。文件选择后等待点击“导账”，切换软件时清空旧附件绑定，避免把旧附件当成新软件输入。
- 域名选项、环境分组及默认选择沿用上传压缩包页面；复用当前登录身份和套餐。
- 启用年月旁解释服务端取较早月份规则。若支持拖放，遵循现有共享输入目录留存规则。

### 提交与结果

1. 检查登录、套餐、账套名称、年月、会计准则、纳税人类型及必填附件；显示可定位到字段的错误。
2. 固定本次请求的身份、套餐、域名、参数和附件，提交企业专业版新建账套请求；处理中禁用重复提交。
3. 收到任务编号后立即保存记录，记录来源软件、账套名称、提交时间、套餐及目标域名；不保存登录凭据。
4. 自动在提交时的域名查询该任务，区分受理、处理中、成功、失败和警告。不能把收到任务编号或收到任意结果对象等同于导账成功。
5. 提供停止查询和从历史继续查询；停止查询不取消服务端任务。查询网络失败允许重新查询，提交响应不确定时不自动重复提交，以免重复新建账套。
6. 展示失败原因、警告、任务编号，以及服务端提供的实际启用年月。界面切换不隐式取消已受理任务。

### 验证与实现边界

- 界面验证覆盖入口、软件切换、必填提示、零余额默认值和小窗口布局。
- 构建验证遵守现有 MSBuild `/nr:false`、产物及中间文件隔离、编译进程归属复核、PDB 服务清理和原启动 EXE/PDB 哈希保护规则。
